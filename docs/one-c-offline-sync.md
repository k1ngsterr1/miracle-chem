# Обмен с офлайн 1С

Этот контур не требует открывать 1С в интернет и не даёт CRM прямой доступ к её файловой или SQL-базе. Рядом с рабочим местом, где открыта 1С, запускается небольшой **Windows Sync Agent**. По расписанию он получает только изменившиеся данные из 1С, формирует JSON и сам отправляет его в CRM по HTTPS. Внешних входящих подключений к компьютеру с 1С не требуется.

## Что нужно настроить один раз

1. На сервере CRM задайте случайный `ONE_C_SYNC_API_KEY` длиной не менее 32 символов. Не храните его в репозитории, в 1С или в общем сетевом файле.
2. В 1С создайте внешнюю обработку или HTTP-сервис чтения, который отдаёт изменения с момента предыдущей успешной выгрузки. Конкретная обработка зависит от конфигурации 1С (УТ, Бухгалтерия, самописная) и её справочников.
3. На компьютере с 1С установите Sync Agent и задайте ему URL `https://<crm-домен>/api/integrations/1c/sync`, ключ и папку очереди. Агент запускается из Планировщика заданий Windows каждые 5–15 минут или после проведения документа.
4. Дайте агенту доступ только на чтение к выгрузке 1С. У CRM должен быть HTTPS-сертификат; ключ передаётся только в заголовке запроса.

## Формат одной дельты

Каждая выгрузка получает новый `batchId`. При повторной отправке того же `batchId` CRM вернёт уже сохранённый результат и повторно остатки не спишет. Для каждого объекта обязателен стабильный GUID/ссылка 1С в `externalId` и время изменения в `updatedAt`.

```json
{
  "workspaceId": "11111111-1111-4111-8111-111111111111",
  "batchId": "1c-2026-08-29T10:15:00Z-0001",
  "generatedAt": "2026-08-29T10:15:00.000Z",
  "source": "1C",
  "customers": [{
    "externalId": "1c-guid-customer-1",
    "updatedAt": "2026-08-29T10:10:00.000Z",
    "name": "ТОО Пример Бетон",
    "taxId": "123456789012",
    "active": true
  }],
  "suppliers": [{
    "externalId": "1c-guid-supplier-1",
    "updatedAt": "2026-08-29T10:10:00.000Z",
    "name": "ТОО Поставщик",
    "active": true
  }],
  "materials": [{
    "externalId": "1c-guid-material-kt1",
    "updatedAt": "2026-08-29T10:10:00.000Z",
    "code": "KT-1",
    "name": "КТ-1",
    "type": "CHEMICAL_ADDITIVE",
    "baseUnit": "KG",
    "costPerBaseUnit": "825",
    "currency": "KZT",
    "minimumStock": "100",
    "productionEligible": true
  }],
  "receipts": [{
    "externalId": "1c-guid-receipt-101",
    "updatedAt": "2026-08-29T10:10:00.000Z",
    "posted": true,
    "number": "ПТ-000101",
    "receivedAt": "2026-08-29T09:30:00.000Z",
    "materialExternalId": "1c-guid-material-kt1",
    "supplierExternalId": "1c-guid-supplier-1",
    "lotNumber": "KT1-240829",
    "quantity": "500",
    "unit": "KG",
    "unitCost": "825",
    "currency": "KZT"
  }]
}
```

Отправка делается `POST`-запросом с заголовками:

```text
Content-Type: application/json
x-one-c-sync-key: <секрет из ONE_C_SYNC_API_KEY>
```

## Правила безопасности и сверки

- В синхронизацию попадут только проведённые поступления (`posted: true`).
- `productionEligible` не вычисляется по названию. Его выставляет утверждённая таблица соответствия номенклатуры 1С; так непроизводственные позиции не попадут на склад реагентов.
- Новая или конфликтующая номенклатура, непроведённое/изменённое поступление и неизвестная связь не меняют остатки. Они попадут в блок «Синхронизация 1С» на странице «Склад», где сотрудник с правами склада подтверждает или отклоняет запись.
- Уже синхронизированное поступление не переписывается автоматически: для разницы оформляют корректировку в CRM и проводят соответствующий документ в 1С. Это сохраняет аудит и реальную себестоимость партии.
- Агент хранит неотправленные JSON-документы в локальной очереди и повторяет отправку с тем же `batchId` после проблем со связью. Удалять файл очереди можно только после ответа CRM со статусом `COMPLETED` или `PARTIAL`.

## Перед запуском в эксплуатацию

Сначала выгрузите одну тестовую дельту в отдельный контур CRM и сверьте 10–20 позиций: код, единицу, цену, поставщика, номер партии и остаток. После этого включайте расписание. Для подготовки реальной внешней обработки нужны название конфигурации 1С, версия платформы и перечень документов/справочников, из которых следует брать клиентов, номенклатуру и поступления.
